# 后端削减 50% 方案

日期：2026-10-28
基线：`integrate/netpulse`，后端 89,900 行（生产 69,597 + 测试 20,303）

## 0. 目标与前提

| 口径 | 现状 | 目标 | 降幅 |
|---|---:|---:|---:|
| 生产代码 | 69,597 | 29,000–32,000 | −54% ~ −58% |
| 测试代码 | 20,303 | 9,000–10,000 | −51% ~ −56% |
| **合计** | **89,900** | **38,000–42,000** | **−53% ~ −58%** |

两个前提必须接受：

1. **纯重构到不了 50%。** 合并重复实现最多约 −35%；剩下部分来自删除外围能力与重写测试。
2. **"功能不变"和"砍一半"不能同时成立。** 下面的能力取舍表需要你确认；保留得越多，能到的降幅越小。

## 2. 三个杠杆

**L1 合并重复实现（约 −25k）**
同一件事存在多份实现：7 个证据/报告输出、6 个存储入口、18 个"Agent"、两套生命周期、两套恢复逻辑、4 份重复小工具。合并后能力不变。

**L2 把"Agent"降级（约 −9k）**
18 个 Agent 里真正需要 LLM 的只有 5 个；其余是确定性校验器。校验器不需要 Agent 框架、状态机包装和重复的 LLM 重试逻辑，直接写成函数。

**L3 删除外围能力 + 重写测试（约 −17k）**
外围能力合计约 6.4k 生产代码，连带约 6k 测试；再把内部 dict 形状测试改为契约测试，可再减 4k。

## 3. 能力取舍表（需要你确认）

### 保留（核心闭环）

意图提交与澄清、语义解析与规划、冲突/安全/容量准入、策略编译、ONOS/P4/TC 执行、读回与流量验证、撤销、决策报告、拓扑与遥测、QoS。

### 合并（能力保留，实现减少）

| 现在 | 合并为 |
|---|---|
| 18 个 Agent（15,704） | 5 个：理解、安全、策略、执行验证、自愈 |
| 6 个 store + `api/store.py`（4,278） | 2 个仓储：意图、运行记录 |
| 7 个证据/报告模块（~6,377） | 1 个证据模型 + 1 个报告构建器 |
| 两套生命周期（6,870） | 1 个状态机 |
| 10 个后台循环 | 3 个：worker、assurance、watcher |

### 建议删除（外围能力，约 6.4k 生产 + ~6k 测试）

| 能力 | 现有代码 | 说明 |
|---|---:|---|
| A2A 传输与证据 | 765 | Agent 间协议，不影响主流程 |
| 经验记忆 | 448 | 案例复用，未成为默认路径 |
| 偏好关系 | 381 | 仅测试覆盖 |
| Soak / 长稳测试框架 | 270 | 属于验证工具，不是产品功能 |
| 生产重启恢复 | 1,655 | 三层恢复互相补偿，改为启动时对账 |
| 故障控制器 | 327 | 自动注入故障，默认关闭 |
| 探针调度器 | 175 | 自动探测，默认关闭 |
| Watcher | 553 | 持续 KPI 监视，默认关闭 |
| Workload 观测 | 126 + worker 片段 | 与意图生命周期重叠 |
| Ingress admission | 630 | 未进入主执行路径 |
| Demo / baseline 快捷路径 | 1,043 | 竞赛演示专用 |

删掉这些后，前端对应的调用（`/demo/*`、`/workloads`、`/audit`、`/experience-memory`、`/a2a`）需要同步移除；这部分改动在 `frontend` 内另行计算。

如果这些能力必须保留，50% 不可达，现实下限是 **55,000–60,000 行（−33% ~ −39%）**。

## 4. 执行批次

每批独立合并、可回滚，结束时报告实际行数与上一批的差额。

| 批次 | 内容 | 预计减少 | 累计后 |
|---|---|---:|---:|
| B0 | 特征测试基线（8 个意图的决策产物） | 0 | 89.9k |
| B1 | 删除外围能力及其测试 | 12,000 | 77.9k |
| B2 | 持久化收敛为 2 个仓储 | 2,900 | 75.0k |
| B3 | 生命周期收敛为 1 个状态机，删兼容桥 | 4,500 | 70.5k |
| B4 | 18 Agent → 5 服务 | 9,200 | 61.3k |
| B5 | 证据/报告 7 → 2，自愈合并 | 4,600 | 56.7k |
| B6 | API 路由分组、infra 合并、去重工具 | 9,000 | 47.7k |
| B7 | 测试重写为契约测试 | 9,500 | 38.2k |

B0 必须先做：没有决策产物的对照基线，B3/B4 无法判断"行为没变"。

B1 可以最先做，因为它不碰核心状态机，立即拿到 13% 降幅。

## 5. 验收

- 每批结束跑 `cloc`/`wc -l`，实际行数写进批次记录；偏离预算超过 15% 时暂停复盘。
- 8 个特征意图在每批前后逐字段比对决策产物（IntentSpec、Plan、Policy、ExecutionResult、DecisionArtifact）。
- CI 全绿；真实网络验收只在 B3 与 B7 后各跑一次。
- 新增代码禁止 `dict[str, Any]` 跨层、禁止 `except Exception`、禁止新增后台循环。
- 删除功能必须在同一批内删掉对应路由、测试和前端调用。

## 6. 为什么能到 50%

不是靠压缩写法，而是因为当前有大量**同一能力的多份实现**：

- 生命周期有 2 个写入者，外加一层兼容桥；
- 证据有 7 个输出模块，字段互相投影；
- Agent 有 18 个，其中 13 个是确定性校验器；
- 存储有 6 个入口 + 1 个 58 方法的门面；
- 恢复有 3 层（restart recovery、recovery manager、recovery readback）；
- 后台循环有约 10 个。

把这些收敛成各一份，生产代码自然落到 30k 左右；再删掉默认关闭的外围能力，总计进入 40k 以内。

## 7. 不做的事

- 不做大爆炸重写；每批必须可单独上线。
- 不在删功能的同时改行为；两者分开提交。
- 不为了行数把多个无关职责塞进一个文件；合并按能力和变更轴，不按文件大小。
